# 官方插件包协议 1

本文约定 1.1.0 的插件仓与宿主边界。实现及设备验收以各自记录为准。

## 源码与运行时

插件仓维护插件实现、平台适配、处理规则、资源、测试与发布清单。本体固定依赖插件仓的一个提交及内容摘要，构建时导入该提交的原生源码。导入文件属于生成依赖，不在本体另行维护副本。

原生适配随宿主编译、签名与审核；运行时下载的 JSON 包提供受限声明及处理内容，不装载动态库、不运行任意脚本。修改原生适配仍需发布新的宿主。下载包可以更新宿主已支持的提示词、映射、资源与模块声明，不能扩大权限。iOS 使用相同约束。

## 统一清单

每个插件有稳定 ID、独立三段版本号、名称、说明、类型、最低宿主版本、SDK 版本、平台适配表、权限需求和贡献内容。类型为 `buffer`、`capsule`、`mailbox`、`extension`。保留现有平台 ID 作为别名，不因移动源码重置用户配置。

预装与下载是分发策略，使用相同的清单验证和生命周期。预装包是签名宿主内的只读来源；卸载通过安装状态隐藏插件，重新安装可以恢复预装版本。卸载不删除用户文档、词库、会话或凭据。

平台适配表只列实际实现的平台；不支持的平台不能安装。Windows 并击是 1.1.0 必须补齐的功能，不能通过清单宣称已有实现。手机的快问、作诗、字符画保留独立身份，不从 macOS 插件数量推导全平台数量。

## 宿主服务

- 宿主负责输入焦点、投递、源文本修订、取消、保护输入框、网络授权和凭据。插件只能通过已声明且用户已授权的能力请求操作。
- Buffer 插件读请求冻结的源内容并返回结果；切换目标、修改原文、停用或卸载后，旧结果不能继续投递。
- Capsule / Mailbox 插件贡献入口、过滤规则和类型化动作。存储、解锁及权限校验仍由宿主完成；隐藏入口不结束已经接受的终端任务。
- 扩展订阅宿主提供的事件；停用必须注销观察、停止捕获并恢复普通输入路径。统计只接收已有的脱敏计数接口。

## 下载与生命周期

目录固定包的 SHA-256、版本、平台及 SDK 要求。下载先在暂存区验证，再原子替换安装内容；失败保留旧版本。新安装默认停用，启用不自动选择为当前 Buffer，也不发起网络请求。

安装身份与启用授权绑定，重装不继承已撤销的授权。状态依次为未安装、已安装停用、启用；下载中单独显示进度。更新或卸载使在途任务失效，保留用户数据。每次加载验证包，拒绝摘要不符、路径穿越、未知贡献类型及不兼容版本。

首个验收插件为 Polisher：测试必须证明下载的指令进入实际请求，并覆盖停用、卸载、摘要损坏、取消及旧结果拒绝，不能只断言清单中出现一个条目。

## 发布证据

插件 CI 生成确定性的 JSON 包、目录、原生源码包和摘要清单；原生源码包记录来源文件及宿主导入路径。宿主 CI 再用固定依赖构建四个平台。安装包签名、设备安装、输入验证、TestFlight 上传与审核、GitHub 公开发布分别记录。
